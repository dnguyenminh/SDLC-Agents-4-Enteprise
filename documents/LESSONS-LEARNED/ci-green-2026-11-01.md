# Lesson Learned — CI Green (SA4E-389/SA4E-390, v1.55.12) — 2026-11-01

Outcome: `CI — Build & Test` (7/7 jobs) + `SA4E-335 — Build & push backend image` GREEN on `origin/main`
(runs 41235413965, 41235413877) after 2 root-cause commits: `0ebdc61`, `7b2b1ec`.

## 1. Read the FAILING STEP's own log before diagnosing
`buildx dial-stdio SIGKILL` printed **after** `##[error]Process completed with exit code 1`
is a runner **cleanup artifact**, not the cause. The real failure was the **Trivy SEC-04 gate**
(`exit-code: "1"`, severity CRITICAL,HIGH): `pypdf 6.21.3` (transitive of
`markdown-exporter-mcp-local`) carries CVE-2026-119203/119204/119205 (HIGH, DoS), fixed in 6.21.4.
- Fix: force-upgrade with version probe in `backend/Dockerfile` (same PEP-440 pattern as
  `pillow`/`certifi` from SA4E-360). The earlier "transient infra SIGKILL" diagnosis was wrong —
  the gate failed **as designed** (BR-19 fail-visible).
- Rule: repeated identical failure ≠ transient. Extract the CVE/assertion table from the job log
  before blaming infra.

## 2. Vitest cross-test pollution via module-level caches
`readProviderTurnConfig()` cached the resolved config at module level; tests mutate a shared
`vscode` config mock, so a stale resolution poisoned later tests (empty emitted tokens,
`PI_MODEL_UNRESOLVED` appearing/disappearing depending on order).
- Fix (production code): key the cache by a **fingerprint of the raw settings** it derives from
  (`JSON.stringify([profiles, activeProfileId, provider, model])`) — a mock change always re-resolves.
- Fix (test hygiene): in `beforeEach`, reset `mockConfigValues` AND `clearSessionHostCache()`
  (session-host registry caches per `workspaceRoot+tabId` at module level).
- Diagnostic trick: run the failing file **alone** vs **with the suite** — alone-pass + suite-fail
  ⇒ cross-test pollution, not a code bug.

## 3. providerId semantics
`providerId` must be `activeProfile.provider` (real provider id for model-registry lookup),
never `activeProfile.id` (profile id is not a provider — breaks builtin-registry resolution and
produces a wrong `PI_MODEL_UNRESOLVED` chat:error).

## 4. Perf "smoke benchmark" failing only on CI
A 10k-iteration latency benchmark (`path-resolver.pbt.test.ts`, mean < 50 ms) failed on CI
because `resolveWorkspacePath` ran **2 `execSync` git commands per call** via
`detectWorktreeType()` when `rootSource === "workspace"`. Fix: memoize `detectWorktreeType()`
per cwd. Lesson: any benchmark that fails only on CI ⇒ the hot path does I/O or environment-
dependent work despite its "NO I/O" doc contract.

## Verification pattern
`tsc --noEmit` → failing files in isolation → failing files together → related suite → push →
watch BOTH workflows (CI Build & Test + backend image) to green.
